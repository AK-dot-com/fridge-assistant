# 🧊 冷蔵庫アシスタント

冷蔵庫にある食材を入力すると、作れるレシピを検索し、不足食材や買い物リストを作成できるWebアプリです。

**デモ**: `index.html` をブラウザで開くか、GitHub Pages で公開してご覧ください。

---

## ① アプリ概要
冷蔵庫にある食材を入力すると、作れるレシピを検索し、不足食材や買い物リストを作成できるWebアプリ。

## ② 対象ユーザー
- 一人暮らしの人
- 共働き家庭
- 食材を無駄にしたくない人
- 献立を考えるのが面倒な人

## ③ 解決する課題
- 献立を考える時間がかかる
- 食材を余らせる
- 同じ料理ばかりになる
- 買い忘れが多い

## ④ 機能一覧
| 機能 | 概要 |
|---|---|
| 食材入力 | タグ形式で追加・削除（Enterで追加、候補表示あり） |
| レシピ検索 | 入力した食材からレシピを横断検索、一致率を算出 |
| レシピ詳細 | 画像（アイコン）・材料・作り方をモーダル表示 |
| 不足食材表示 | 持っている食材との差分だけを抽出・色分け表示 |
| 買い物リスト | 不足食材をワンタップで追加、チェック・削除可能（LocalStorage保存） |
| お気に入り | ☆ボタンでレシピを保存（LocalStorage保存） |

## ⑤ 画面一覧
```
TOP（検索） → 検索結果 → レシピ詳細（モーダル）
                ↓
           お気に入り / 買い物リスト
```
3つの画面はボトムナビ（PCではヘッダー内タブ）で切り替える1ページ構成（SPA的なタブ切り替え）です。

## ⑥ 使用API
| API | 用途 |
|---|---|
| `recipes.json`（ローカルJSON、`fetch()`で取得） | レシピ検索 |

> **補足**: 楽天レシピAPI（カテゴリ別ランキング取得API）はカテゴリ単位の取得のみに対応しており、「持っている食材から横断検索する」という本アプリの核となる要件には対応していません。そのため同一階層の `recipes.json` を `js/api.js` から実際に `fetch()` して取得する構成にしています（`cache: 'no-store'` で毎回リクエストが発生し、ブラウザの開発者ツールのNetworkタブでも通信が確認できます）。オフライン時やHTTPエラー・JSON破損時のエラーハンドリングも本物の `fetch()` の失敗に対して動作します。実際の外部API（食材横断検索に対応したAPI）に差し替える場合は、`js/api.js` の `RECIPES_JSON_URL` を実APIのエンドポイントに変更し、レスポンス形式の読み替え部分だけ書き換えれば移行できます。

## ⑧ データ設計

入力食材:
```json
{
  "ingredients": ["卵", "玉ねぎ", "ベーコン"]
}
```

お気に入り:
```json
{
  "id": 1234,
  "title": "親子丼"
}
```

`recipes.json`（APIレスポンスを模したレシピ本体データ）:
```json
{
  "meta": { "source": "local-mock", "count": 14 },
  "recipes": [
    {
      "id": 1,
      "title": "親子丼",
      "emoji": "🍚",
      "thumbBg": "#FFE4D6",
      "time": 20,
      "rating": 4,
      "category": "ごはんもの",
      "ingredients": ["卵", "鶏肉", "玉ねぎ", "めんつゆ", "米"],
      "steps": ["米を炊いておく。鶏肉と玉ねぎを一口大に切る。", "…"]
    }
  ]
}
```

## ⑨ LocalStorage設計
| キー | 内容 |
|---|---|
| `favoriteRecipes` | お気に入りレシピの配列 |
| `shoppingList` | 買い物リスト `[{id, name, checked}]` |
| `theme` | `light` \| `dark` |
| `recentSearch` | 直近の検索食材タグ（最大5件） |

## ⑩ エラー仕様
- API失敗 → 赤いアラートで「通信エラーです / 時間を置いてもう一度お試しください」を表示（「もう一度試す」ボタン付き）
- 検索0件 → 「該当するレシピはありません」を表示
- 検索欄が空のまま検索 → 「食材を1つ以上入力してください」を表示
- 検索フォーム下の「オフラインモードをテスト」チェックボックスで、通信エラー時の表示を動作確認可能

## ⑪ ローディング
検索中はスケルトンカード（3件）と「レシピを探しています…」のテキストを表示。

## ⑫ レスポンシブ
ブレークポイント: `375 / 768 / 1024 / 1440`
- 375px〜: 1カラム、ボトムナビ
- 768px〜: 2カラム
- 1024px〜: 3カラム、ヘッダー内タブに切り替え（ボトムナビは非表示）
- 1440px〜: 4カラム

## ⑬ アクセシビリティ
- 画像（絵文字アイコン）に `role="img"` と `aria-label`
- フォーム部品に `aria-label` / `label` 相当のテキスト
- キーボード操作: `Enter`でタグ追加、`Escape`でモーダルを閉じる、`Tab`でフォーカス移動可能
- `:focus-visible` によるフォーカスリングの明示
- 結果・エラー領域に `aria-live` / `role="alert"` を付与
- `prefers-reduced-motion` に対応

## ローカルでの動作確認
ビルド不要です。`index.html` をブラウザで直接開くか、任意の簡易サーバーで配信してください。

```bash
npx serve .
# または
python3 -m http.server 8000
```

## GitHub Pagesでの公開

2. リポジトリの Settings → Pages → Branch を `main` / `/(root)` に設定
3. 発行されたURLでアクセス
